# Структура проекта Агентной Системы Поддержки

## Основные директории и файлы

- **`RLT_project/`** — Основной Django-проект, содержащий логику веб-приложения и API.
  - **`accounts/`** — Приложение для управления пользователями и аутентификацией.
  - **`chat/`** — Приложение для реализации логики чата пользователя с агентом.
  - **`rag/`** — Приложение и логика Retrieval-Augmented Generation (RAG). Содержит индексаторы, роутеры, инструменты для нормализации запросов и основную логику обращения к векторной базе.
    - `chunker.py` — Разделение текста на чанки.
    - `indexer/` — Индексация документов.
    - `normalize_query.py` — Нормализация пользовательских запросов.
    - `router.py` — Маршрутизация запросов к нужным коллекциям базы знаний.
    - `main_rag.py` — Точка входа для RAG-конвейера.
  - **`support_files/`** — Дополнительные статические/вспомогательные файлы для бэкенда.
- **`dataset/` / `txt_dataset/`** — Директории для хранения сырых и обработанных данных базы знаний (инструкции, статьи, нормативные документы).
- **`qdrant_storage/`** — Локальное хранилище векторной базы данных Qdrant (содержит эмбеддинги статей и товаров).
- **`rlt_tender_guide/`** — Дополнительные руководства и вспомогательные скрипты.
- **`scripts/`** (Корневые `.py` файлы) — Скрипты для сбора, обработки данных и администрирования.
  - `convert_docs.py`, `check_instructions.py`, `check_sitemap.py`, `extract_sitemap_kb_urls.py`, `finalize_categories.py`, `finalize_kb.py`, `inspect_article_structure.py`, `process_all_datasets.py`, `update_dataset_all_articles.py`, `test_full_system.py`, `test_fetch_utf8.py`.

## Отдельные компоненты системы

### 1. Парсер (Scraper)
Отвечает за сбор актуальной информации с Портала Поставщиков (zakupki.mos.ru). 
- Собирает статьи из Базы знаний (инструкции для поставщиков и заказчиков).
- Собирает информацию о товарах, работах и услугах (категории, цены, характеристики).
- Собирает открытые данные по закупкам и контрактам.

### 2. Подсистема RAG (Retrieval-Augmented Generation)
- **Векторная база данных (Qdrant)**: Хранит семантические представления (эмбеддинги) всей собранной информации.
- **Поиск**: При получении вопроса от пользователя, система ищет наиболее релевантные куски текста в базе.
- **Генерация**: Найденный контекст передается LLM вместе с вопросом пользователя для формирования точного ответа со ссылками на первоисточник.

### 3. Веб-интерфейс (Django)
Обеспечивает взаимодействие пользователя с системой:
- Авторизация и профили пользователей.
- Чат-интерфейс для общения с агентом-консультантом.
- API для фронтенда или интеграций.
