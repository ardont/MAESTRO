# Архитектура Агентной Системы Поддержки

## Обзор
Система представляет собой интеллектуального ассистента поддержки (Support Agent) на базе архитектуры RAG (Retrieval-Augmented Generation). Она предназначена для автоматизации обработки запросов пользователей на портале `zakupki.mos.ru`.

## Основные компоненты

1. **Пайплайн сбора данных (Data Ingestion)**
   - Находится в папке `scripts/`.
   - Забирает эталонные инструкции через GraphQL API сайта, очищает от HTML-разметки и формирует чистый датасет в формате JSON.
   - Подробнее см. `parsing_pipeline.md`.

2. **Движок индексации и чанкинга (Indexer & Chunker)**
   - Находится в `RLT_project/rag/indexer/`.
   - Читает датасет, режет его на логические фрагменты (чанки) в зависимости от типа документа (законы по статьям, инструкции по заголовкам).
   - Преобразует текст в векторные представления (эмбеддинги) с помощью модели `ru-en-RoSBERTa`.
   - Сохраняет данные в векторную БД **Qdrant**.

3. **Интеллектуальный маршрутизатор (Router & Guardrails)**
   - Находится в `RLT_project/rag/router.py`.
   - `check_guardrails()`: Блокирует токсичный или нецензурный контент.
   - `route_support_line()`: Классифицирует вопрос пользователя по линиям поддержки (L1 - Общая, L2 - Техническая, L3 - Юридическая/Экспертная).
   - Выставляет теги категорий, которые потом используются как фильтры при поиске в БД.

4. **Генератор ответов (RAG Engine / LLM)**
   - Находится в `RLT_project/rag/main_rag.py`.
   - Принимает нормализованный запрос, ищет релевантные факты в Qdrant с учетом фильтров маршрутизатора.
   - Отправляет найденный контекст в локальную LLM через `Ollama` для формирования вежливого, структурированного и точного ответа со ссылками на первоисточник.
   - Подробнее см. `rag_engine.md`.
